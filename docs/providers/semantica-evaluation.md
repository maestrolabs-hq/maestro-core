# Semantica evaluation

**Research basis.** Primary Semantica sources were reviewed at the `main` tree and release `v0.6.7`; Maestro sources were reviewed locally. Isolated wheel and MCP probes were used to verify the 0.6.7 package surface. No live provider state, home configuration, or MCP configuration was changed.

## Executive summary

- Latest stable release is **0.6.7**, released 2026-08-28, under **MIT**. [Semantica v0.6.7](https://github.com/semantica-agi/semantica/releases/tag/v0.6.7) · [pyproject.toml](https://github.com/semantica-agi/semantica/blob/main/pyproject.toml) · [LICENSE](https://github.com/semantica-agi/semantica/blob/main/LICENSE)
- It is a Python package (>=3.8; 3.11+ recommended) with a very large core dependency set, not a small Rust-native add-on. [Installation](https://github.com/semantica-agi/semantica/blob/main/docs/installation.md) · [pyproject.toml](https://github.com/semantica-agi/semantica/blob/main/pyproject.toml)
- It ships an MCP server, but the documented/current modular server is **stdio JSON-RPC**, one in-memory graph per process, optionally loaded from `SEMANTICA_KG_PATH`; the reviewed 0.6.7 wheel exposes 15 tools and four resources. [mcp/README.md](https://github.com/semantica-agi/semantica/blob/main/mcp/README.md) · [mcp/session.py](https://github.com/semantica-agi/semantica/blob/main/mcp/session.py)
- Graph construction and query are available in-memory, JSON/Markdown persistence, and external graph/vector backends; no native multi-repository global graph registry was found. [ContextGraph](https://github.com/semantica-agi/semantica/blob/main/semantica/context/context_graph.py) · [graph-store config](https://github.com/semantica-agi/semantica/blob/main/semantica/graph_store/config.py)
- **Accepted direct-phase risk (high):** Direct installation accepts Semantica's dependency footprint and persistence limitations while explicitly not treating Semantica as Maestro's ledger and preserving the direct integration boundaries. [README.md](../../README.md) · [ADR 0001](../adr/0001-paths-are-derived-never-written.md) · [ledger.md](../ledger.md)

## Findings

1. **Release, license, platform/runtime (low risk).** `v0.6.7` is marked non-draft/non-prerelease and was published 2026-08-28; the release contains a universal Python wheel and source archive. The package declares MIT and Python `>=3.8`; classifiers say OS Independent and Python 3.8–3.12, while installation docs list Windows/Linux/macOS and recommend Python 3.11+. [Release](https://github.com/semantica-agi/semantica/releases/tag/v0.6.7) · [pyproject.toml](https://github.com/semantica-agi/semantica/blob/main/pyproject.toml) · [installation.md](https://github.com/semantica-agi/semantica/blob/main/docs/installation.md)

2. **Exact installation and footprint (high risk).** Basic installation is `pip install semantica`; source installation is `git clone …; pip install -e .`; extras are selected as `semantica[...]`. The core dependency list includes NumPy, pandas, SciPy, scikit-learn, UMAP, spaCy, Transformers, PyTorch, sentence-transformers, RDFLib, NetworkX, plotting/Jupyter packages, FAISS CPU, FastEmbed, ONNX Runtime, document parsers, GitPython, and PyArrow. Graph backends and LLM clients are optional extras; the `all` bundle is substantially larger. [installation.md](https://github.com/semantica-agi/semantica/blob/main/docs/installation.md) · [pyproject.toml](https://github.com/semantica-agi/semantica/blob/main/pyproject.toml)

3. **MCP invocation/transport/tools (medium risk).** The package metadata provides `semantica-mcp`; the reviewed 0.6.7 wheel reads newline-delimited JSON-RPC 2.0 on stdin and writes responses on stdout, with logs on stderr. Its MCP surface exposes 15 tools: `extract_entities`, `extract_relations`, `record_decision`, `query_decisions`, `find_precedents`, `get_causal_chain`, `add_entity`, `add_relationship`, `run_reasoning`, `get_graph_analytics`, `export_graph`, `get_graph_summary`, `query_graph`, `update_node`, and `delete_node`. Semantic search uses `query_graph` with `mode: "search"`. It also advertises four `semantica://` resources. A client configuration needs a working Python environment and `cwd` pointing to the Semantica checkout when using the module form. [mcp/README.md](https://github.com/semantica-agi/semantica/blob/main/mcp/README.md) · [mcp/server.py](https://github.com/semantica-agi/semantica/blob/main/mcp/server.py) · [pyproject.toml](https://github.com/semantica-agi/semantica/blob/main/pyproject.toml)

4. **Build and graph model (medium risk).** `GraphBuilder.build()` accepts raw text, extracted objects, or dictionaries of entities/relationships; defaults for raw text use local ML/pattern extraction and do not require an API key, while LLM extraction is explicit. It supports optional entity merge/resolution, conflict handling, temporal validity, history, and snapshots. `ContextGraph` is an in-memory graph with nodes, typed directed edges, adjacency/type indexes, traversal, keyword query, analytics, decisions, provenance, and GraphRAG-related operations. [GraphBuilder](https://github.com/semantica-agi/semantica/blob/main/semantica/kg/graph_builder.py) · [ContextGraph](https://github.com/semantica-agi/semantica/blob/main/semantica/context/context_graph.py) · [README](https://github.com/semantica-agi/semantica/blob/main/README.md)

5. **Storage, updates, queries, portability (high risk).** Context graphs can be saved/loaded as JSON and, in 0.6.7, round-tripped as managed Markdown; JSON contains graph identity, nodes, edges, and links. The MCP server loads one JSON graph at startup when `SEMANTICA_KG_PATH` is set; otherwise state is in memory. External graph stores include Neo4j, FalkorDB, Apache AGE, and Amazon Neptune; RDF/triple-store support includes embedded Oxigraph plus remote stores; vector stores include FAISS, Qdrant, Weaviate, Milvus, Pinecone, and PgVector. [mcp/README.md](https://github.com/semantica-agi/semantica/blob/main/mcp/README.md) · [explorer-setup.md](https://github.com/semantica-agi/semantica/blob/main/docs/explorer-setup.md) · [ContextGraph](https://github.com/semantica-agi/semantica/blob/main/semantica/context/context_graph.py) · [graph-store `__init__.py`](https://github.com/semantica-agi/semantica/blob/main/semantica/graph_store/__init__.py)

6. **Atomicity/corruption concern (high).** The documented `ContextGraph.save_to_file()` writes JSON directly with `open(path, "w")`; the source does not show a temp-file/fsync/atomic-replace protocol for that JSON path. Consequently, process or power failure during write can leave a truncated file. External stores have their own transaction semantics, but this review found no single Semantica-wide commit protocol spanning graph, vectors, and memory. The 0.6.7 changelog itself records a prior Oxigraph persistence/flush fix, so backend-specific lifecycle testing is required. [ContextGraph source](https://github.com/semantica-agi/semantica/blob/main/semantica/context/context_graph.py) · [v0.6.7 changelog](https://github.com/semantica-agi/semantica/releases/tag/v0.6.7)

7. **Global/multi-repository graph (high gap).** Semantica supports cross-graph links and durable link metadata, but the MCP session is a single lazy `ContextGraph` singleton per server process and exposes one `SEMANTICA_KG_PATH`. No native repository registry, project-scope key, or multi-repository merge policy was identified in the reviewed primary sources. A global graph would therefore require an application-level graph file/backend and namespace policy. [mcp/session.py](https://github.com/semantica-agi/semantica/blob/main/mcp/session.py) · [cross-graph change](https://github.com/semantica-agi/semantica/commit/867ecfda1b8ce9f7efa5f4cfc444c8b097590d13) · [Maestro protocol](../protocol.md)

8. **Embeddings, LLMs, local compatibility (medium risk).** Supported embeddings include Sentence-Transformers, FastEmbed, OpenAI, BGE, and Ollama local embeddings. Providers include OpenAI, Anthropic, Gemini, Mistral, Llama, Groq, Cohere, Azure, Bedrock, Ollama, DeepSeek, and others through provider code/LiteLLM. An OpenAI-compatible endpoint is supported with `provider="openai"`, `base_url`, model, and API key; the provider restricts the URL scheme to HTTP(S). The official discussion documents vLLM/LM Studio usage and Ollama; llama.cpp is not explicitly documented, so feasibility depends on its OpenAI-compatible server surface and structured-JSON behavior, not a native llama.cpp adapter. [README](https://github.com/semantica-agi/semantica/blob/main/README.md) · [providers.py](https://github.com/semantica-agi/semantica/blob/main/semantica/semantic_extract/providers.py) · [Discussion #552](https://github.com/semantica-agi/semantica/discussions/552)

9. **Security/privacy (high).** Raw-text ingestion can be local, but choosing cloud providers or remote graph/vector backends sends data outside the process; credentials are supplied through provider/database configuration. The release notes mention SSRF hardening for integrations, while the OpenAI provider only validates URL scheme, so network reachability and endpoint trust remain deployment responsibilities. Persisted JSON/Markdown contains graph content, metadata, provenance, and decisions and must be treated as sensitive. [pyproject.toml](https://github.com/semantica-agi/semantica/blob/main/pyproject.toml) · [v0.6.7 release](https://github.com/semantica-agi/semantica/releases/tag/v0.6.7) · [providers.py](https://github.com/semantica-agi/semantica/blob/main/semantica/semantic_extract/providers.py)

10. **Skills and overlap with Maestro providers (high gap).** Semantica's README claims plugin bundles/skills for several agent products including Codex CLI, but the reviewed sources do not identify a Pi-specific skill. Semantica overlaps this work's graph/context concerns but remains an independent integration boundary from Maestro providers: it is a Python graph/context/LLM platform with different durability and execution assumptions. [Semantica README](https://github.com/semantica-agi/semantica/blob/main/README.md) · [local `README.md`](../../README.md) · [local `docs/adr/0001-paths-are-derived-never-written.md`](../adr/0001-paths-are-derived-never-written.md) · [CGC](./cgc.md) · [Graphify](./graphify.md) · [local repository tree](https://github.com/maestrolabs-hq/maestro-core/tree/main)

## Risks carried into the direct phase

- **High:** the dependency footprint is large and needs ordinary package/security review. [pyproject.toml](https://github.com/semantica-agi/semantica/blob/main/pyproject.toml)
- **High:** direct JSON writes are not an atomic persistence protocol and are not a substitute for Maestro's ledger. [ContextGraph source](https://github.com/semantica-agi/semantica/blob/main/semantica/context/context_graph.py) · [ledger](../ledger.md)
- **Medium:** the single MCP graph is configured as one workspace-global file by this deployment; Semantica does not provide a repository registry. [mcp/session.py](https://github.com/semantica-agi/semantica/blob/main/mcp/session.py)
- **Medium:** local llama.cpp compatibility depends on its OpenAI-compatible endpoint and structured-output behavior. [Discussion #552](https://github.com/semantica-agi/semantica/discussions/552)

## Approved direct integration design

Install `semantica==0.6.7` as-is and run the direct `semantica-mcp` stdio server. Use the HOME-derived workspace path `<workspace>/.maestro/state/providers/semantica/global-graph.json` for the workspace-global graph, initially seeded only from `maestro-core` through native repository ingestion. Keep Semantica's identity and results independent from CGC, Graphify, and MemPalace. Expose all 15 native wheel tools and document the inconsistent native mutation persistence rather than adding a proxy or persistence layer. [local ADR](../adr/0001-paths-are-derived-never-written.md) · [mcp/README.md](https://github.com/semantica-agi/semantica/blob/main/mcp/README.md)

## Open items after the direct phase

1. Whether Semantica should gain transactional mutation handling in a later Maestro integration.
2. Which llama.cpp server/version and structured-output contract should be supported beyond the initial local check.
3. What retention and deletion guarantees are required for graph content, embeddings, provenance, and exported files.
